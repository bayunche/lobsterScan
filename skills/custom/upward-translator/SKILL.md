# Upward Translator · 表达教练

## 何时触发
- pipeline step == `upward_optimization`
- **在 humanizer 之前跑**;顺序固定:本 skill → humanizer → reviewer 检测

## 何时不触发
- 用户在 supplement 明说"保持原文措辞" → 只做风险显化和数据前置,不改语气
- ReportCore 来自领导原话 / 客户邮件 → 透传,不替对方改口

## 方法论 · 四原则

### 1. 结论前置(summary 必须先说总体判断)
| 部门视角 | 领导视角 |
|---|---|
| 本周完成多项客户对接,推进若干内部流程优化 | 本周整体进度正常,完成 18 个客户回访,12 个确认推进;1 风险待决:数据库扩容延期 |
| 做了几次需求评审,讨论了下一步方向 | 需求基本对齐,下周一进开发,需 3 人/周资源 |

### 2. 数据前置(动词改主动 + 量化)
| 部门视角(模糊) | 领导视角(具体) |
|---|---|
| 推进了多项工作 | 完成 18 个客户回访,12 个确认推进 |
| 性能有所提升 | P95 延迟 320 ms → 180 ms,降 44% |
| 风险已识别 | 数据库扩容延期 2 周,影响 Q3 上线 |
| 客户反馈不错 | 5 个客户调研,4 个明确续约意向 |

### 3. 风险显化但不升级
- **显化**:`{item, impact}` 的 impact 必须是业务影响,可被领导评估
- **不升级**:不替决策者下结论
- ✅ "数据库扩容延期 2 周 → Q3 上线可能延 1 周,需评估是否调资源"
- ❌ "数据库扩容延期,后果严重,**必须立即**开会决策"(替领导拍板)

### 4. 诉求具体到 owner + 动作
| 模糊 | 具体 |
|---|---|
| 需要协调资源 | 借调 2 名后端,owner: 技术总监,时间: 下周一前 |
| 希望领导关注 | 需领导拍板是否调资源支援 Q3 上线(owner: 领导,本周内) |

## 与 humanizer 的边界
| 关注点 | upward-translator | humanizer |
|---|---|---|
| 视角(部门 → 领导) | ✅ | 不管 |
| 数据前置 | ✅ | 不管 |
| 风险显化 | ✅ | 不管 |
| 句子像不像 AI | 不管 | ✅ |
| 词汇套话 | 部分(下面禁用词清单) | 全面 |
| 句长节奏 | 部分(短句优先) | 全面 |

**两个 skill 都跑,顺序不能错**:upward-translator 先把内容立起来,humanizer 再去 AI 腔。

## 反模式 · 禁用词清单(出现即扣分)

**国产 AI 套话(CHINESE-AI-PHRASES):**
赋能 / 抓手 / 闭环 / 链路 / 落地 / 沉淀 / 心智 / 复盘起来 / 拉齐对齐 / 打法 / 跑通 / 跑顺 / 颗粒度 / 形成合力 / 底层逻辑 / 本质上 / 说白了

**模糊量词(必须替换成具体数字):**
多项 / 若干 / 大量 / 较多 / 显著 / 大幅 / 总体来看 / 基本完成 / 接近完成

**替决策者下结论的措辞(必须改成中性陈述):**
必须 / 应当 / 务必 / 一定要 / 强烈建议 → 改成「建议」/「可考虑」/「请评估」

## Schema
输入和输出**都是 ReportCore**,只改内容不动 schema。
- summary / key_points / risks / support_needed / next_steps 重写
- data_gaps 保留原样(不要写成"完整")
- progress_status 不变(那是 point-extractor 算出来的)

## 自检清单
- [ ] `summary` 结论前置(第一句就是总体判断)?
- [ ] 每条 `key_point` 含具体数字?
- [ ] 每条 `risk.impact` 用业务语言(而非"严重 / 重要")?
- [ ] 每条 `support_needed` 含 owner + 具体动作?
- [ ] 全文没出现禁用词清单任意一条?
- [ ] 没有"必须 / 务必 / 一定要"等替领导拍板的措辞?
- [ ] `data_gaps` 透传(没擅自改写成"完整 / 无缺")?
- [ ] schema 字段名一个没改?
