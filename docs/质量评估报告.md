> **评估基线**:`docs/原始资料/PRD.docx`(12651 字完整通读)
> **评估范围**:13 自研 skill + 17 第三方 skill + `pipeline.py` / `harness.py` / `agent_backend.py` / `render/*`
> **评估时间**:2026-05-26
> **方法论**:并行两路深度子智能体(skill 与 pipeline 各一路独立读 + 给报告),交叉验证后综合

## 执行摘要

**结论**:项目骨架扎实、5 大产物链路全通,但**在 PRD 验收关键点上有 5 处具体违规**,集中在 UX 原则、refine 链路、HTML 页数下限。Skill 层有 1 个核心 skill(material-parser)严重过时是第一棒掉地的隐患,9 个孤儿 video-toolkit skill 在污染 video-producer agent 的上下文。

**总体可用性**:能跑出"摘要 + 讲稿 + HTML + 视频 + 审校"5 件套,但其中 3 件套在严格按 PRD Story 验收标准下会被打回,需要至少 6-8 小时 P0 修复工作才能闭环。

## 四、Pipeline 架构层评估

### 健康项 ✅

- **harness 事件驱动**(`harness.py:212-389`):`max_revisits=2 / max_hops=16` 真挂在 Coordinator,熔断收尾正确
- **agent_backend 动态 LLM 路由**(今日新加):每 turn 重读 openclaw.json,管台改即生效
- **render 三层兜底**:mmx → edge-tts (TTS) → playwright record → PIL+ffmpeg slideshow,**任何 provider 全挂仍能产 mp4**
- **JSON 宽松解析**(`client.py`):LLM JSON 不严谨时不让 pipeline 死

### 风险项 ⚠️

| 风险 | 严重度 | 位置 | 说明 |
|---|---|---|---|
| Refine API 是 stub | 🔴 P0 | `api/tasks.py:117-120` | PRD §8 5 按钮全废 |
| HTML 1 分钟模式 <5 页 | 🔴 P0 | `pipeline.py:273` | DURATION_PROFILE 1分钟 chapters_n="3-4" 直接低于 PRD "≥5 页"硬指标 |
| 多处用户可见路径有技术 ID 泄漏 | 🔴 P0 | `page.tsx:191` / `harness.py:285,344` | PRD UX 红线 |
| 审校 ≥3 条无后端兜底 | 🟡 P1 | `pipeline.py:1640` | LLM 给少了直接落盘 |
| `_gate_review` 重做不走 harness 不计 max_hops | 🟡 P1 | `pipeline.py:2400` | 死链可能(虽仅 1 次) |
| 上游 fail 时下游用空 prev 硬跑 | 🟡 P1 | `harness.py:336-352` on_failed 兜底永 emit 下一棒 | 优点是 pipeline 不 abort、缺点是产物质量崩 |

### 4 类 report_type × 4 类 audience × 3 时长 **矩阵覆盖度**

PRD 要求 48 组合,**skill 层实际只覆盖 3 时长**(DURATION_PROFILE 真值表)。`report_type` 和 `audience` 在 prompt 里仅作字符串注入,没有专属章节模板 / 语气替换表:

- ❌ report-structure 不区分 4 类报告,全统一 cover/summary/completed/risks/next_steps 模板。**PRD 述职类的"挑案例 + 不夸大"** 缺专属处理
- ❌ copywriter / upward-translator 都没给"对直属领导 vs 对客户 vs 对跨部门"的语气替换表
- reviewer 的 `audience_fit` 只是 boolean,没 4 类受众判定细则

## 五、跨层系统性问题

1. **Schema 真值漂移链**:material-parser 写一套字段(completed/in_progress) → pipeline.py:604 描述另一套(facts/persons/risks) → point-extractor 期望第三套。三处不一致,目前靠 LLM 容错走通——脆弱。
2. **降级协议无统一**:5 个 video/TTS skill 各写各的失败 JSON,backend 没法靠 skill 输出判定 degrade,**全靠 try/except + slideshow_video.py 兜底**——能交付但靠 backend 救场,不是协议级保证。
3. **agent 工作区污染**:`claude-code-video-toolkit/CLAUDE.md` + 9 个孤儿 skill 全在 video-producer 同根目录下,**LLM 必然被诱导走错链路**。
4. **mmx CLI 优先策略漂移**:MEMORY 说 minimax 4 skill 应 mmx CLI 优先,实际 minimax-tts/minimax-video 仍是裸 python,只 minimax-music 走了 mmx。
