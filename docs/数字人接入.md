## 一、Provider 注册表与切换

`apps/web-backend/app/video/providers.py:REGISTRY` 是唯一真值。当前 5 条目：

| id | 状态 | video skill | tts skill | 主要场景 |
| --- | --- | --- | --- | --- |
| `minimax` | ✓ implemented | `minimax-video`（Hailuo） | `minimax-tts` | V0 默认，单段 6s 短镜头 |
| `heygen` | ✓ implemented | `heygen`（V2） | `heygen`（同 skill，内置 TTS） | 真人 lip-sync，**需要 API credits 非 Studio credits** |
| `kling` | ✓ implemented | `klingai`（本地等价） | `minimax-tts`（Kling 不出语音） | 国内可灵，单段 5s |
| `self-hosted-sadtalker` | ✗ 占位 | sadtalker | local-tts | 待接 GPU 节点 |
| `none` | ✓ implemented | — | — | 仅 SRT 字幕 |

切换 provider：改 `openclaw/openclaw.json` 的 `video.provider` 字段（管台 Config 也能改）：

```json
"video": {
  "provider": "kling",
  "model":    "kling-v3",
  "avatar_id":        null,
  "voice_id":         "de6ad44022104ac0872392d1139e9364",
  "talking_photo_id": "6013fc758b5446a2ba17d8c459538bb4"
}
```

后端 `resolve_from_openclaw_json()` 读它，挑出对应 `VideoProvider` 实例并按用户配置覆盖（model / avatar_id / voice_id / talking_photo_id），不污染 REGISTRY 单例。

## 二、汇报形态：开场结尾插入

数字人**不全程出镜** — 只在 broadcast 第 1 页和最后 1 页插入，中间页保留印刷工艺设计 + slides 数据展示。

```
┌─────────────────────────────────────────────────────────┐
│ broadcast.html 总长度（举例 1 分钟汇报）                │
├──────────┬─────────────────────────────────┬────────────┤
│ intro    │  middle pages（数据 + slides）   │  outro     │
│ 5-6s     │  ~40-50s                         │  5-6s      │
│ 数字人 + │  无视频，audio narration drive    │ 数字人 +    │
│ audio    │  page advance                    │ audio       │
└──────────┴─────────────────────────────────┴────────────┘
```

### avatar slide media schema

`html_builder.py` 在重渲 broadcast.html 时给 intro / outro 两页注入 avatar media：

```python
if avatar_key:
    av = video_meta.get(avatar_key) or {}   # video_meta = video_production.json
    av_path = av.get("path") if isinstance(av, dict) and av.get("ok") else None
    if av_path:
        media = {
            "kind": "avatar",
            "video": _video_file_url(Path(av_path)),
            "video_duration": av.get("duration") or 5.0,
            # avatar 段音频独立轨：videoEl muted+loop，audioEl 驱动 advance
            "audio": _audio_file_url(Path(av["audio_path"])) if av.get("audio_path") else "",
        }
```

### broadcast.html JS 播放逻辑

avatar 页跟 middle 页不一样：

| 页类型 | video | audio | advance 信号 |
| --- | --- | --- | --- |
| middle | 无 | 有（narration mp3） | audio `ended` |
| avatar | 有（数字人嘴动）muted + loop | 有（独立 TTS mp3） | audio `ended` |

为啥这样设：

- 数字人 video 自带嘴动，但**不知道讲什么话**，跟 backend TTS 的旁白对不上口型 — 所以 video muted。
- video 是 5s 但 audio 可能 6-7s，让 video loop，audio 跑完才推下一页。
- 已加 CSS `.slide.has-avatar .body { visibility: hidden }` — avatar 页隐藏正文，让数字人占满。
- `.avatar-overlay { position: absolute; inset: 0; z-index: 50 }` — overlay 盖在 slide 上层。

## 三、HeyGen V2

### Provider config

```python
"heygen": VideoProvider(
    voice_id="de6ad44022104ac0872392d1139e9364",          # Xiaoxin Professional
    talking_photo_id="6013fc758b5446a2ba17d8c459538bb4",  # Veronica
    required_env=["HEYGEN_API_KEY"],
    notes="V2 API · 真人 lip-sync。账号实测 1281 avatars + 5469 talking_photos + 2414 voices",
)
```

### Skill 接入要点

- 单个 `heygen` skill 包揽 video + TTS — TTS 由 voice_id 选，HeyGen 内置（不调外部 TTS）。
- 三维 ID 体系正交：`avatar_id`（虚拟形象）/ `talking_photo_id`（真人静态照片 → 动起来）/ `voice_id`（声音）。
- character_arg 优先级：`talking_photo_id`（账号 5469 个，主推）→ `avatar_id`（1281 个）。优先级在 `providers.py:297` 体现。
- API endpoint：`POST /v2/video/generate` 提交，`/v1/video_status.get?video_id=` 查询（V1/V2 混用是 HeyGen 官方设计）。
- Auth：`x-api-key` header（不是 Bearer）。

### ⚠️ Credits 陷阱

HeyGen 账号有两个 credit 池子：

| 池子 | 用途 | 跑视频用哪个 |
| --- | --- | --- |
| Studio credits | Web 后台「生成视频」按钮 | ✗ 不能用 |
| API credits | `POST /v2/video/generate` | ✓ 必须有 |

错误码 `MOVIO_PAYMENT_INSUFFICIENT_CREDIT` 就是 Studio 有但 API 空。在 HeyGen 后台 → Settings → Billing → API Plans 充值才行，跟 Studio 完全分开购买。

## 四、Kling AI（国内）

详见 [Kling-API接入说明.md](Kling-API接入说明.md)。这里只列与 provider 相关的要点：

- `video_skill = "klingai"`，**TTS 复用 `minimax-tts`**（Kling 平台本身不出语音）。
- 单段上限 5s — 不要试 `--duration 10` 会被 SKILL 拒。所以采「两段 5s 并行」：intro 5s + outro 5s。
- 模型走 `kling-v3` / `kling-v3-omni` / `kling-v2-6` / `kling-video-o1`。
- **必须用国内域名** `https://api-beijing.klingai.com` — env 变量 `KLING_API_BASE` 控制，默认就是国内。

### prompt 模板（providers.py `_KLING_TEMPLATE`）

按 audience / style 动态拼角色和服饰：

```python
audience_role = {"直属领导": "女性", "团队内部": "女性", ...}.get(audience, "女性")
style_dress = {
    "简洁正式": "深色现代职业装",
    "成果突出": "白衬衫加西装外套",
    "问题导向": "简约浅灰职业装",
    "述职风":   "正装深色西装",
}.get(style, "现代职业装")
```

agent 拿到 prompt 后调 2 次 `kling.mjs video`（intro 一次 outro 一次），分别 `mv` 到 `data/outputs/<task>/video/intro.mp4` 和 `outro.mp4`。

## 五、MiniMax Hailuo（V0 默认）

- 单段 6s 短镜头。比 Kling 多 1s，比 HeyGen 便宜，无 lip-sync 但作开场镜头够用。
- video 模型须用 TokenPlan 配额覆盖的型号（`MiniMax-Hailuo-2.3-Fast-6s-768p` 等），其它型号会 `quota_exhausted`。
- TTS 用同家 `minimax-tts` skill，走 mmx CLI 优先。

### MiniMax 双通道路由

```python
MINIMAX_TOKENPLAN_VIDEO_MODELS = {
    "MiniMax-Hailuo-2.3-Fast-6s-768p",  # plan 计量名（含 -6s-768p 后缀）
    "MiniMax-Hailuo-2.3-6s-768p",
    "MiniMax-Hailuo-2.3",               # mmx CLI 真 API id（无后缀）
    "MiniMax-Hailuo-2.3-Fast",
}

def classify_minimax_channel(video_model, tts_model) -> "tokenplan" | "payg":
    # 任一 model 不在 plan 集合 → 整体走 PAYG（两个 skill 在同一 subprocess
    # 里只能注一把 key，从严）
    ...
```

> ⚠️ 命名空间陷阱：plan 配额面板用「计量名」（含 `-6s-768p`），mmx CLI 真 API 用基础名。两套都列在 `MINIMAX_TOKENPLAN_*` 里，避免 user 改 model 后 routing 漂移到 PAYG。详见 [[minimax-dual-channel]]。

## 六、TTS 与 backend 兜底

不管 video provider 是谁，**audio 都可能由 backend 单独生成**（数字人段 + 中间页都可能）：

| 触发场景 | 谁产 audio |
| --- | --- |
| Hailuo provider | agent 走 minimax-tts skill（mmx CLI） |
| HeyGen provider | HeyGen 内置 TTS（voice_id 选音）|
| Kling provider | backend `_ensure_audio_segments` 走 mmx CLI / edge-tts |
| 任意 provider 数字人 fail → slideshow fallback | backend `_ensure_audio_segments` 补全 intro/outro/middle |

`_ensure_audio_segments`（`pipeline.py`）策略：

1. 先尝试 mmx CLI（`mmx speech synthesize --text --model --voice --out`）— 独立 auth 不读 MINIMAX_API_KEY。
2. mmx 不可用 → 走 `tts_fallback.py` 的 edge-tts（微软 Edge 浏览器的 TTS endpoint，免 key）。
3. 全部失败 → 该段 ok=false，走 anullsrc 静默占位（broadcast 不卡，但那段是哑剧）。

> ⚠️ 不能把"没 MINIMAX_API_KEY"等价为"TTS fail"。mmx CLI 走 `~/.config/mmx/config.json` 独立 auth — 必须实际调脚本拿 `via` 字段才能判定。providers.py `_MINIMAX_TEMPLATE` 重点强调了这点。

## 七、管台配置

数字人 provider 的所有可调字段都通过管台 Config 页落到 `openclaw.json`：

```
管台 → Config → Video Provider
  ├─ provider     下拉  (minimax / heygen / kling / sadtalker / none)
  ├─ model        下拉  (按 provider.available_video_models)
  ├─ avatar_id        文本框  (HeyGen 限)
  ├─ voice_id         文本框  (HeyGen 限)
  └─ talking_photo_id 文本框  (HeyGen 限)

管台 → Secrets
  ├─ HEYGEN_API_KEY
  ├─ KLING_ACCESS_KEY_ID
  ├─ KLING_SECRET_ACCESS_KEY
  ├─ MINIMAX_API_KEY            (Hailuo TokenPlan key)
  └─ MINIMAX_API_KEY_PAYG       (Hailuo PAYG key，可选)
```

参考 [[provider-config-everywhere]] / [[minimax-dual-channel]]。

## 八、新接一个 provider 的步骤

1. 在 `skills/custom/<id>/` 写 SKILL.md + scripts（用 clawhub `<id>-dev/<id>` 包做参考；本地等价 = ABI 对齐即可，未来可被官方包覆盖）。
2. 在 `apps/web-backend/app/video/providers.py:REGISTRY` 加一条 `VideoProvider(...)`。`implemented=False` 占位先合并不会破现网；接好再切 True。
3. 在 `providers.py` 加 prompt 模板（`_<ID>_TEMPLATE`），在 `build_prompt_for_provider` 里加 if 分支。
4. 数字人 ID 类字段（avatar_id / voice_id 等）按 provider 自决，参考 HeyGen 的三维拆分。
5. 管台 Config 下拉自动从 `available_video_models` / `available_tts_models` 取，不用动前端。
6. Secrets：在 admin-backend 的 secrets 白名单（`apps/admin-backend/app/api/secrets.py`）加 env 名，让管台 UI 能填。
7. 写测试任务跑端到端，验证 `recording.mp4` 有 audio stream（`ffprobe`）+ 时长对齐 totalSec。
