## 1. 范围与术语

### 1.1 范围
本系统由 **三部分** 组成，必须 **一并交付**：

| 模块 | 简称 | 职责 |
| --- | --- | --- |
| **业务应用** | 会汇报 | 面向最终用户：录入零散材料，产出摘要 / 讲稿 / HTML 汇报页 / 数字人视频 / 审校建议 |
| **OpenClaw 集群** | 八大 Agent | 完成汇报材料生成的"虚拟团队"：协作完成材料整理 → 重点提炼 → 表达优化 → 文案 → 页面 → 视频 → 审校 |
| **OpenClaw 管理平台** | 管台 | 面向开发/运营：注册管理 Agent、维护 SOUL/AGENTS/USER、挂载 Skill、配置 Channel binding、查看会话、监控集群与任务流水线 |

> 三部分共用同一套 OpenClaw 内核与配置（`~/.openclaw/`），但业务应用与管理平台是 **两套独立前后端**，定位、用户、权限、UI 都不同。

### 1.2 术语
- **OpenClaw** — Actor 模型的多 Agent 运行时；Gateway 路由消息，Brain 跑 LLM 推理（ReAct）。
- **Agent** — 一个具备独立 workspace（含 `SOUL.md`/`AGENTS.md`/`USER.md`）、独立 `agentDir`（`~/.openclaw/agents/<id>/`）、独立 session 历史的虚拟成员。
- **SOUL.md** — Agent 的人格 / 价值观 / 行为准则，最高优先级注入 system prompt。
- **AGENTS.md** — Agent 的操作手册 / 模型与工具配置 / 跨 Agent 协议，长会话后自动补回。
- **USER.md** — 用户/领域偏好，影响输出风格。
- **Skill** — `<skill>/SKILL.md` + 可选 `references/`、`scripts/`、`assets/` 的能力包；按 SKILL.md 的 `description` 触发。
- **Channel Plugin** — 把外部入口（Web 业务应用、IM、CLI）接入 Gateway 的插件。
- **Binding** — `(channel, accountId, peer, …) → agentId` 的路由规则。
- **Pipeline / 流水线** — 一次汇报生成任务从 Coordinator 触发到 Reviewer 完成的全过程。
- **TaskRun** — 一次具体执行（含若干 Agent step / message / artifact / event）。

### 1.3 与 PRD 的差异说明（优化点）
PRD 给出了产品需求与 Agent 分工，但未细化：① Agent 的输入/输出契约；② Skill 选型；③ 集群与业务应用的交付协议；④ 管理平台。本文档全部补齐，并对 PRD 中的几个点做了工程优化：

- **视频生成不堵塞主链路**：摘要 / 讲稿 / HTML 先返回，视频后台异步产出（PRD §13.3 已暗示，本文档明确接口与 SSE 事件）。
- **集群展示业务化**：进度卡片只露 8 个业务化阶段；Agent ID / Run ID / 错误码全部在后端日志保留，前端只显示可读文案（PRD §11.3）。
- **审校 Agent 不只是"打分"**：执行 Humanizer Skill 做"AI 套话扫描" + 结构完整性检查（重点 / 问题 / 影响 / 诉求 / 计划是否齐全）+ 字数 / 时长复核，给出可触发"再短一点 / 更突出问题"的快捷指令。
- **HTML 与视频共享一份"演示工程"**：基于 garden-skills 的 `web-video-presentation`（16:9、`narrations.ts` 为口播与帧时间轴 single source of truth），同一份 Vite + React 工程既能浏览器投屏（HTML 汇报页），又能 `?auto=1` 录制（视频底片），避免双链路。
- **数字人形象通过 HeyGen / SadTalker 二选一**：MVP 优先 HeyGen（托管，开箱），自托管路径用 `digitalsamba/claude-code-video-toolkit` 的 SadTalker + Qwen3-TTS。

### 2.1 技术栈

## 3. OpenClaw 集群设计

### 3.1 部署形态

```
~/.openclaw/
├── openclaw.json              ← Gateway / agents 列表 / bindings 总配置
├── agents/
│   ├── coordinator/
│   │   ├── auth/              ← per-agent 认证（不可跨 agent 复用！）
│   │   ├── models/            ← provider 注册
│   │   └── sessions/          ← 会话历史 JSONL
│   ├── material/   …
│   └── reviewer/
└── workspaces/
    ├── coordinator/
    │   ├── SOUL.md
    │   ├── AGENTS.md
    │   ├── USER.md
    │   ├── notes/
    │   └── .agents/skills/    ← 该 agent 可见的 skill 包
    ├── material/  …
    └── reviewer/
```

> **重要约束（来自官方文档）**：`agentDir` 严禁跨 Agent 复用，否则 auth / session 串扰。本项目 8 个 Agent 各自独立目录。

### 3.2 Gateway 与 Channel Plugin

业务应用通过 **自研 Channel Plugin `huihuibao-web`** 接入 Gateway：
- 协议：WebSocket，消息体 `{ channel: "huihuibao-web", accountId, peerId, content, attachments }`
- Binding：`channel:huihuibao-web,accountId:<userId> → agentId:coordinator`
- coordinator 是唯一外部入口，其它 7 个 Agent 通过 coordinator 的 `@mention` 触发，session 隔离用 `agent:<id>:huihuibao-web:user:<userId>:task:<taskId>`。

### 3.3 SOUL / AGENTS / USER 文件分工

| 文件 | 内容 | 何时更新 |
| --- | --- | --- |
| `SOUL.md` | 该 Agent 是谁、说话风格、最高优先级原则（如"绝不虚构数据"） | 部署期由管理平台模板生成，可手动微调 |
| `AGENTS.md` | 模型选择、tool 列表、可调用的 Skill、跨 Agent 协议（输入字段 / 输出字段 / 错误码） | 每次新增 Skill / 改协议时更新 |
| `USER.md` | 当前用户偏好（汇报对象、惯用风格、行业术语词典） | 由业务后端在每次任务前根据用户档案动态写入 |

### 3.4 跨 Agent 通信协议（核心约定）

所有 Agent 之间用 **结构化 JSON 消息**（封装在 `@mention` 文本里），统一 schema：

```jsonc
{
  "msg_type": "task.step.request",       // 或 task.step.result / task.step.error
  "task_id": "trk_2026_05_15_001",       // 后端可见，前端不展示
  "run_id":  "run_…",
  "step":    "point_extraction",         // 见 §9.1 阶段枚举
  "from":    "coordinator",
  "to":      "point-extractor",
  "payload": { /* 见 §4 各 Agent 输入字段 */ },
  "context": {
    "report_type": "project_progress",
    "audience": "直属领导",
    "duration": "3分钟",
    "style":    "简洁正式"
  }
}
```

错误对外业务化（前端只展示 `生成时间较长，请稍后重试…`），原始 `error_code` 仅写入后端日志与管理平台。

## 4. 八大 Agent 详细规格

> 命名遵循 OpenClaw 习惯：小写 + 短横线 ID；展示名前端用中文。

### 4.1 `coordinator` · 统筹 Agent
- **展示名**：汇报总控
- **SOUL 摘要**：你是基层管理者的汇报助手项目经理。先列出"我打算怎么做"再开干；任何 Agent 失败先重试一次，再降级（如视频失败也要先把 HTML 与讲稿交付）。绝不在 user 可见输出里出现 task_id / agent_id。
- **Skills**：无（纯调度）
- **输入**：用户表单 + 上传文件元数据
- **输出**：`TaskRun` 状态机 + 最终汇报包指针
- **关键提示词骨架**：参见 `docs/Agent-Prompts/coordinator.md`

### 4.2 `material` · 材料整理 Agent
- **展示名**：资料员
- **职责**：把零散文本、上传文件解析为「素材池」：完成事项 / 进行中 / 问题 / 关键数据 / 支持诉求 / 计划 / 相关人。
- **Skills**：
  - `kb-retriever`（处理多文件知识库）
  - 自研 `material-parser`（针对 docx / xlsx / pdf / md / txt 的字段抽取器）
- **输入 schema**：
  ```jsonc
  { "raw_text": "…", "files": [{"path":"…","mime":"…"}], "hints": {"time_range":"本周"} }
  ```
- **输出 schema**：见 §8.2 `MaterialPool`
- **质量门**：若 raw 字段总长 < 50 字 且无文件，返回 `need_more_input`，由 coordinator 触发前端补充提示。

### 4.3 `point-extractor` · 重点提炼 Agent
- **展示名**：分析师
- **职责**：在 MaterialPool 上提炼一句话总结 + ≤3 个重点 + 进度判断 + 风险 + 诉求 + 计划。
- **Skills**：自研 `point-extractor`（提示词 + 规则校验）
- **关键规则**（从 PRD §10.3 落到代码）：
  1. 优先结果与影响；
  2. 弱化过程；
  3. 问题必须带影响；
  4. 诉求必须具体到对象 / 动作；
  5. 缺少数据 → 输出 `data_gap` 而非编造。
- **输出 schema**：见 §8.3 `ReportCore`

### 4.4 `structure` · 汇报结构 Agent
- **展示名**：结构设计师
- **职责**：按汇报类型（日常 / 进度 / 述职 / 介绍）从模板库选大纲。
- **Skills**：自研 `report-structure`（YAML 模板库 `assets/report-structures/*.yaml`）
- **输出**：`Outline` 对象（章节列表、每章字段映射）

### 4.5 `upward-opt` · 向上汇报优化 Agent
- **展示名**：表达教练
- **职责**：把"部门视角 / 流水账"改成"领导视角"——结论前置、风险显化、诉求明确。
- **Skills**：
  - `humanizer`（28 类 AI 套话扫描 + 二次"还像不像 AI"自审 + voice mimic）
  - 自研 `upward-translator`（领导视角句式库 + 反例库）
- **运行模式**：humanizer 在第二轮上跑，第一轮仍由 upward-translator 主导（防止 humanizer 把"领导风"也清洗掉）。

### 4.6 `copywriter` · 文案生成 Agent
- **展示名**：文书
- **职责**：基于 ReportCore + Outline + 优化后表达，生成：① 一句话摘要；② 1/3/5 分钟口播稿（PRD §10.5）；③ 每页页面文案。
- **Skills**：自研 `copywriter`（含口播稿字数计算器 / TTS 友好标点规整）
- **关键约束**：3 分钟版 500-750 字；必须包含下一步计划；段落与 `narrations.ts` 步数 1:1。

### 4.7 `html-designer` · HTML 设计 Agent
- **展示名**：设计师
- **职责**：生成"既能投屏、也能录视频"的演示工程。
- **Skills**：
  - `web-design-engineer`（避 AI 套配色、设计 token、checkpoint 流程）
  - `web-video-presentation`（16:9 1920×1080、`narrations.ts` 为 SSOT、`?auto=1` 录制接口）
  - `gpt-image-2`（封面 / 关键页插画 / 数字人头像底图，Mode B 走 host 原生即可）
- **关键约束**：
  - 每页一个核心主题；
  - 必须包含 PRD §10.6 列出的 6 页结构；
  - 严禁 Title Case 中文标点 / emoji 替代图标；
  - `narrations.ts` 的步数 = 章节内步数 = TTS 段数。
- **产物**：`outputs/<task>/web-presentation/`（Vite 工程）+ 编译后的 `dist/`（HTML 可直接打开）

### 4.8 `video-producer` · 视频生成 Agent
- **展示名**：视频制作
- **职责**：基于 `html-designer` 产出工程 + `copywriter` 产出讲稿生成 1-3 分钟 MP4。
- **Skills**：
  - **方案 A（MVP 默认，托管）**：`heygen-avatar` + `heygen-video`（v3 Video Agent pipeline，输入头像 + 讲稿 + 选定 voice，输出 share link + MP4）
  - **方案 B（自托管 / 内网）**：`digitalsamba/claude-code-video-toolkit`
    - `elevenlabs` 或 `qwen3_tts.py` 做 TTS
    - `playwright-recording` 录 web-presentation `?auto=1`
    - `sadtalker.py` 把头像底图 + 配音变成数字人头部画面
    - `ffmpeg` 合成最终 MP4 + 字幕
  - 字幕：从 `narrations.ts` 按时间轴自动切分（每条 ≤12 字）
- **降级**：视频失败 → 仅交付 HTML + 讲稿 + 摘要 + 审校，前端给"视频生成中 / 失败，可稍后重试"业务化提示。

### 4.9 `reviewer` · 审校 Agent
- **展示名**：质量检查员
- **职责**：对最终包做 PRD §10.8 检查项 + Humanizer 二次扫描 + 时长复核，输出 ≥3 条可执行建议 + 快捷指令按钮（`再短一点` / `更突出问题` / `更正式一点` / `更突出成果`）。
- **Skills**：
  - `humanizer`（侦测 28 种 AI 套话残留）
  - 自研 `report-reviewer`（结构完整性 / 数据一致性 / 时长字数）

### 5.2 自研 Skill（按 SKILL.md 自然语言风格组织）

| 自研 Skill | 接入 Agent | 关键内容 |
| --- | --- | --- |
| `material-parser` | `material` | docx/xlsx/pdf/md/txt 解析规则 + 字段抽取提示词 + 解析失败降级（建议用户复制核心内容） |
| `point-extractor` | `point-extractor` | 一句话 / 三重点 / 进度判断 / 风险 / 诉求 / 计划的提示词 + 结构校验脚本 |
| `report-structure` | `structure` | 4 种类型 × 大纲 YAML 模板（assets/report-structures/） |
| `upward-translator` | `upward-opt` | 领导视角句式库、反例库、风险/诉求改写规则 |
| `copywriter` | `copywriter` | 1/3/5 分钟字数表、TTS 友好标点、章节-narration 对齐器 |
| `report-reviewer` | `reviewer` | 8 项检查 + 快捷指令映射 + 输出业务化建议 |

### 5.3 Skill 选型决策

| 场景 | 选择 | 理由 |
| --- | --- | --- |
| HTML 视觉骨架 | `web-design-engineer` 先行，`gpt-image-2` 补封面/插画 | 反 AI 套路、design token 化、避免"AI 味" |
| HTML→视频共底片 | `web-video-presentation` | `narrations.ts` 同时驱动 TTS 与帧切换，避免双链路漂移 |
| 数字人 | **MVP 用 HeyGen**，V1.0 给管理平台一个"自托管 SadTalker" 开关 | 比赛 Demo 最快出片；自托管路径保留 |
| 去 AI 化 | `humanizer` | 28 类套话识别 + 自审 pass，符合 PRD §10.8 审校诉求 |
| 文件解析 | `kb-retriever` + 自研 `material-parser` | 既能跨多文件检索，也能定向抽字段 |

> ⚠️ **humanizer 在中文上的注意点**：它的基础知识来自维基百科"AI writing signs"（偏英文）。落地时在 `upward-opt` 的 SKILL.md 里追加 *中文 AI 套话词表*（如"赋能 / 抓手 / 闭环 / 链路 / 落地 / 沉淀 / 心智"），并允许用户提交 2-3 段历史汇报作为 voice sample。

## 6. 业务应用 · "会汇报"

### 6.1 前端规格

#### 6.1.1 路由
| 路径 | 页面 | 说明 |
| --- | --- | --- |
| `/` | 首页 / 创建任务 | 汇报类型卡片 + 材料输入 + 设置（对象 / 时长 / 风格） + 开始生成 |
| `/tasks/[taskId]` | 任务进度 + 结果页 | 单页：上半部分进度卡片，下半部分结果区（摘要 / 讲稿 / HTML / 视频 / 审校） |
| `/tasks` | 历史任务（V1.0） | 列表 + 复用模板 |

#### 6.1.2 组件清单（重点）
- `ReportTypePicker` — 4 种类型卡片（PRD §10.1）
- `MaterialInput` — 文本粘贴 / 文件上传 / 表单切换；文件 mime 校验，失败提示 PRD §9.2 文案
- `ReportSettings` — 对象 / 时长 / 风格
- `GenerationProgress` — 7 张业务化进度卡片（PRD §9.3）：`正在整理材料` → `正在提炼工作重点` → `正在优化向上汇报表达` → `正在生成汇报稿` → `正在生成 HTML 页面` → `正在生成配音视频` → `正在检查汇报质量`；通过 SSE 收 `task.event`
- `ResultSummary` / `ResultScript` / `ResultSlides` / `ResultVideo` / `ResultReview` — 5 个结果区，每个有"复制 / 下载 / 重新生成"按钮
- `QuickActionBar` — `再短一点` / `更正式一点` / `更突出问题` / `更突出成果` / `重新生成某一段`

#### 6.1.3 文案与禁忌（PRD §11.3 / §9.3）
- 进度区严禁出现 `Agent ID` / `task_id` / `run_id`；
- 错误：用 `生成时间较长，请稍后重试，或减少输入材料后再次生成。` 而非 `MODEL_TIMEOUT`；
- 下载文件名用中文 + 时间戳：`本周项目进度汇报_20260515.mp4`。

#### 6.1.4 设计语言
- 直接套用 `web-design-engineer` 的 6 步流程 + 反 AI 套路：
  - **禁用**：紫→粉渐变、emoji 当图标、圆角卡片+彩色 accent border、Title Case 中文标题；
  - **首选**：oklch 色板、CSS Grid、CSS 自定义属性 token、placeholder 用 `[icon]` 而非伪造图标。

### 6.2 后端 / Channel Plugin 规格

`apps/web-backend/`，FastAPI + Uvicorn：

- `POST /api/tasks` — 创建任务（持久化 `Task` + 启动 coordinator）
- `GET  /api/tasks/{id}` — 查任务详情（含已生成的 artifacts）
- `GET  /api/tasks/{id}/events` — **SSE**：实时推送 §9 阶段事件
- `POST /api/tasks/{id}/refine` — 触发快捷指令（再短一点 / 更突出问题…）
- `POST /api/files` — 上传素材，返回 `file_id`（写 `data/uploads/<task>/`）
- `GET  /api/tasks/{id}/exports/{kind}` — 下载（kind: `summary` / `script` / `html` / `video`）
- Channel Plugin `huihuibao-web` — 通过 OpenClaw SDK 与 Gateway 建立 WS 连接，把上述任务转写为消息发给 `coordinator`，并把 Gateway 回流的事件转 SSE 给前端。

### 6.3 API / 事件协议

详见 §9 与 `docs/API接口规范.md`（独立文件）。

## 9. 流水线与事件协议

### 9.1 阶段枚举（前端固定 7 卡片 + 后端可细分 9 步）

| 后端 step | 业务化标签（前端展示） | 负责 Agent |
| --- | --- | --- |
| `task_received` | （隐式：任务已创建） | coordinator |
| `material_parsing` | 正在整理材料 | material |
| `point_extraction` | 正在提炼工作重点 | point-extractor |
| `structure_building` | （合并入下一阶段） | structure |
| `upward_optimization` | 正在优化向上汇报表达 | upward-opt |
| `copywriting` | 正在生成汇报稿 | copywriter |
| `html_design` | 正在生成 HTML 页面 | html-designer |
| `video_production` | 正在生成配音视频 | video-producer |
| `review` | 正在检查汇报质量 | reviewer |

### 9.2 SSE 事件 schema（业务后端 → 前端）
```jsonc
// event: task.step
{ "step": "html_design", "status": "running", "progress": 0.4 }

// event: task.artifact
{ "kind": "summary" | "script" | "slides" | "video" | "review",
  "ready": true, "url": "/api/tasks/.../exports/script" }

// event: task.done
{ "status": "done | partial | failed", "review_id": "…" }

// event: task.message  (业务化错误)
{ "level": "info | warn | error",
  "text": "视频生成时间较长，已先返回讲稿与 HTML，可稍后查看视频。" }
```

### 9.3 Agent ↔ Agent 失败与重试
- **重试 1 次**（同 Agent 同 step），失败再切降级路径：
  - `video-producer` 失败 → 跳过、`task.done` 状态为 `partial`，前端视频区显示重试按钮。
  - `material` 解析失败 → 改用 LLM 兜底（直接读原文），并提示用户"建议复制核心内容到文本框"。
- 错误码白名单后端日志可见；前端只展示业务化文案。

## 14. 风险与对策

| 风险 | 表现 | 对策 |
| --- | --- | --- |
| Humanizer 把"领导风"也清洗成"白开水" | 输出过于平淡 | `upward-opt` 跑两遍：先 `upward-translator` 转视角，再 `humanizer` 去 AI 套话；reviewer 跑第三遍只做检测不重写 |
| `narrations.ts` 与讲稿不同步 | TTS 段数 ≠ 章节步数 → 视频错位 | 在 copywriter 输出时直接生成 `narrations.ts` 草案，html-designer 必须以此为 SSOT，CI 加 assertion |
| HeyGen 配额 / 网络 | 视频卡死 | 配置中心一键切自托管 SadTalker；前端展示业务化"视频生成中" |
| 用户输入太散导致 hallucination | 编造数字 | point-extractor 严格输出 `data_gaps`；reviewer 检查数字是否出现在 material_pool 中 |
| 集群部署复杂度 | 评委演示翻车 | docker-compose 一键 + 预生成 demo task 的快照（无网也能放） |
| 前端泄露技术 ID | PRD §11.3 红线 | 在 SSE 网关层做字段白名单过滤；写一个 lint 规则 |
| Skill 升级破坏兼容 | SKILL.md 改字段 | submodule 锁 sha；CI 跑 `tests/integration/skills/*` 探活 |
